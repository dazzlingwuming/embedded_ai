# 换电脑继续开发

代码仓库：`git@github.com:dazzlingwuming/embedded_ai.git`。开发板已经烧录固件时，新电脑只需安装 PC 后台、配置密钥和开发板 IP，就能继续使用网页、摄像头和语音对话；不需要先安装 ESP-IDF 或 Node.js。

## 1. 下载代码和安装后台

Windows 需要 Git、64 位 CPython **3.12**。也支持 Python 3.11；暂不支持 3.13 及以上，因为现有音频转换使用标准库 `audioop`，该模块在 3.13 移除。安装系统 Python 不会由本项目脚本代办。

在计划存放项目的目录打开 PowerShell：

```powershell
git clone git@github.com:dazzlingwuming/embedded_ai.git
cd embedded_ai
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-console.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-console.ps1
```

未配置 GitHub SSH 时，可将第一条替换为：

```powershell
git clone https://github.com/dazzlingwuming/embedded_ai.git
```

如果 Python 未加入 PATH，指定它的路径：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-console.ps1 -Python C:\Python312\python.exe
```

脚本在项目 `.tools/python` 创建虚拟环境，在 `.cache/pip` 和 `.cache/tmp` 保存下载缓存和临时文件，使用 `requirements.txt` 中固定的版本。后台外部依赖为 `aiohttp` 及其传递依赖；`pyserial` 用于串口日志工具，`Pillow` 用于本地图像筛选和 JPEG 校验。安装走 Direct，不使用 7900 代理，不修改系统代理或系统 Python 包。已有可用环境且版本一致时直接复用；如果需要更改依赖而本项目后台仍在运行，脚本会拒绝安装，保留服务。

`-DryRun` 只读取 Python 版本、包版本并做离线导入检查，不创建环境、不下载、不调用云服务或开发板。不要从旧电脑复制 `.tools/python`：虚拟环境含原电脑 Python 的绝对路径，不能靠整体拷贝迁移。

## 2. 迁移密钥和本地配置

仓库中只有模板。可以从旧电脑**私下复制**以下文件到新电脑相同的项目相对位置：

- `api_key/.env`：DeepSeek 与阿里云密钥；若使用独立语音密钥，也复制 `api_key/realtime.env`。
- `local/ai.json`：DeepSeek 模型及输出设置。
- `local/realtime.json`：阿里云 API Host、ASR/TTS 模型、音色、音量及打断设置。
- `local/wifi.json`：仅在需要重新编译开发板 Wi-Fi 配置时迁移。
- `local/pc.json`：可复制，但需要核对其中 `board_url` 是否仍正确。

不要将密钥、Wi-Fi 密码或这些私有配置提交到 Git。录音、摄像头截图、历史数据和日志需要时另行备份；源码同步不会自动迁移它们。也不要复制旧的 `local/console.pid`。

如果从模板重新配置，下面命令只补齐缺失文件，不覆盖已有配置：

```powershell
New-Item -ItemType Directory -Path .\api_key,.\local -Force | Out-Null
if (!(Test-Path .\api_key\.env)) { Copy-Item .\config\api_key.env.example .\api_key\.env }
if (!(Test-Path .\local\ai.json)) { Copy-Item .\config\ai.example.json .\local\ai.json }
if (!(Test-Path .\local\realtime.json)) { Copy-Item .\config\realtime.example.json .\local\realtime.json }
```

用编辑器在 `api_key/.env` 填入 `DEEPSEEK_API_KEY` 和 `ALIYUN_API_KEY`。阿里云 `api_host` 填其控制台提供的**主机名**，不带 `https://` 或路径，并与密钥所属地域/业务空间匹配。可以继续用原电脑的有效配置；模板的 Host 留空，必须补上后才能语音通话。`proxy` 保持空字符串表示 Direct。

当前语音线路固定为 **开发板麦克风 → 云 ASR → DeepSeek → 云 TTS → 开发板喇叭**。安装后台不会下载本地语音模型，也不会自动消费 API。

## 3. 连接开发板并启动

先给开发板供电。电脑与开发板须在能够互通的局域网，开发板连接的是 2.4 GHz Wi-Fi。电脑可使用网线、2.4 GHz 或 5 GHz，只要网络之间允许互通。

从路由器设备列表或开发板串口日志找到当前 IP，把下方示例地址替换为实际地址：

```powershell
.\scripts\start-console.ps1 -Board http://192.168.1.100 -Background
```

打开 <http://127.0.0.1:8765/>。`127.0.0.1` 是当前电脑上的后台；开发板地址是另一个局域网 IP。页面中的连接设置可以保存板子新地址到 `local/pc.json`。显式 `-Board` 可避免沿用旧电脑的地址。

Wi-Fi 传输摄像头、麦克风和喇叭数据；Type-C 用于供电、串口和烧录。仅换电脑通常不需要重新烧录。如果换了路由器/SSID/密码，开发板必须先连上可用网络，PC 端填一个新 IP 并不能替开发板改 Wi-Fi。

需要关闭后台时，先在网页结束语音通话和录制，再运行：

```powershell
.\scripts\stop-console.ps1
```

离线检查可运行：

```powershell
.\.tools\python\Scripts\python.exe -B -m unittest discover -s tests -p test_*.py -v
```

不要把 `scripts/check-*.py` 一概当成离线测试：其中一些会连接真实开发板或调用收费云 API，需先阅读各脚本参数说明。

硬件诊断使用的生成数据不随源码上传：声学检查需要 `data/cloud-speech-check.wav`，由 `scripts/check-cloud-speech.py` 生成；长朗读检查需要 `data/deepseek-long-stream-check.json`，由 `scripts/check-deepseek-long-stream.py` 生成。这两个生成步骤都调用收费 API，不属于安装或离线单测。准备实际联测时先阅读脚本参数、配置密钥，再按此顺序准备相应文件；不要为了安装后台而运行它们。

## 4. 需要修改和编译固件时

`setup-console.ps1` **只安装 PC 后台**，不安装 ESP-IDF。固件使用 ESP-IDF **5.5.4**，现有脚本约定：

| 项目相对位置 | 内容 |
| --- | --- |
| `.tools/esp-idf-v5.5.4` | ESP-IDF 5.5.4 源码及对应子模块 |
| `.tools/idf-tools/tools` | IDF `tools.json` 指定的 RISC-V 编译器、CMake、Ninja 等 |
| `.tools/idf-tools/python_env/idf5.5_py3.12_env` | IDF 自己的 Python 3.12 环境，与后台环境分开 |
| `.cache/components`、`.cache/pip` | 组件及 Python 包缓存 |
| `.build/gateway` | 固件构建输出 |

新电脑需要按 [ESP-IDF 5.5.4 Windows 安装说明](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32p4/get-started/windows-setup.html)准备工具。使用项目内的源码和工具目录，并让 IDF 工具安装器读取该版本的 `tools.json`；不要仅复制后台虚拟环境后认为固件工具链也已安装。现有构建脚本固定使用上述 IDF Python 目录，需使用 Python 3.12 为 IDF 创建环境。安装过程中同样应将 `IDF_TOOLS_PATH` 指向本项目 `.tools/idf-tools`，把缓存和临时目录放到本项目 `.cache`。

`scripts/env.ps1` 会将项目临时映射为 `P:`，避免中文路径影响编译器；如果新电脑的 `P:` 已被其他磁盘或映射占用，需要先自行选择不冲突的安排，脚本不会删除别人的映射。`scripts/activate.ps1` 加载项目工具链及 Direct 网络环境。

组件版本记录在 `firmware/main/idf_component.yml` 及依赖锁文件。核心依赖包括 `esp_codec_dev`、`esp_wifi_remote`、`esp_hosted` 和 `esp_video`。AEC/VAD 使用仓库中的官方最小 DSP 组件：ESP-SR 2.6.2 和 ESP Audio Effects 1.4.5，含必需的三个 `.a` 库、头文件、许可证与来源记录，不需要下载离线 ASR/TTS 模型。若这部分文件损坏，可阅读并运行 `scripts/prepare-speech-dsp.py` 恢复官方组件；它会联网下载并校验文件。

准备好工具链后，如需更新 Wi-Fi，先复制 `config/wifi.example.json` 到 `local/wifi.json` 并填写实际信息，然后：

```powershell
# 只编译，不碰开发板
.\scripts\build-gateway.ps1 -BuildOnly

# 需要烧录时，先确认新电脑分配的实际 COM 口
Get-CimInstance Win32_SerialPort | Select-Object DeviceID,Name
.\scripts\build-gateway.ps1 -Port COM7
```

`COM7` 只是示例。换 USB 口或电脑后 COM 编号可能变化；这不会改变后台通过 Wi-Fi 使用开发板的方式。不要在正在通话或录制时烧录。
