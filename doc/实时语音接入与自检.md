# 云 ASR → DeepSeek → 云 TTS：使用与验证

当前固件 0.6.0 与本机后台使用独立 ASR、DeepSeek、TTS。声音由开发板麦克风输入、开发板喇叭输出，
默认支持自动插话。没有接入原生语音问答模型，也没有安装本地识别、合成或唤醒模型。

2026-11-13 的 PC 视觉接入在每轮 ASR 最终文字进入 DeepSeek 前附带至多一张本地选中的近期画面，
保留现有 TTS 与打断通路。查看 [视觉上下文与问题清单](视觉上下文与问题清单.md) 了解选帧规则、无图处理和实际验证边界。

## 使用

打开 <http://127.0.0.1:8765/>，更新后刷新页面，进入「AI 助手」，点击「开始语音通话」。
显示「等你说话」后对板载麦克风说话。对方回答时可以直接说“等等”或提出新问题；
也可点「打断播报」。点「结束通话」关闭本次连接。

在「云语音配置」可调整音量 0～100、对话方式及插话检测时长，结束通话后保存，下次通话生效。
自动打断需要板端 AEC/VAD ready；可选择轮流说话回退模式。

用户明确要求全文、逐字朗读或详细解释时，系统按要求完整完成，不擅自改为摘要或要求反复说“继续”。
默认通话上限 600 秒，可设 0 为不限时；到时若当前回答尚在正常生成或播放，会完成这一轮再结束。
手动结束或插话仍立即停止当前回答。原始 WAV 录音与通话互斥，视频走独立通道。

网页关闭不会自动结束后台通话，离开前应主动结束。运行中的 ASR 音频输入有相应云服务用量。
网络故障会结束本次通话，不自动重放旧音频或重新发起收费请求。

## 流式、长文与上下文

DeepSeek 使用 SSE 逐片返回文字，首 TTS 任务与文字请求并行准备，首个自然短片段尽早发声，
后续按较完整的短句合成。音频按 20ms 片段进入有界队列，边生成、边合成、边播放。
不会先收完整篇再一次合成，也不会用 30 秒音频、2000 字或 90 秒整轮计时截断正常朗读。

文字模型输出预算默认 8192 token；服务明确返回 length 时，使用同模型官方 Prefix Completion 继续流式输出。
无法完整完成时会明确报错，不把截断伪装为完整结束。连接与实际网络读取保留超时，
但等待播放队列的正常背压不计入云网络读取超时。

`tts_inactivity_seconds=30` 只限制等待下一个云事件时持续没有数据的情况，
不是音频总时长，也不包含等待本机播放队列。

插话由板上 VAD 与云 ASR 文字共同确认。确认后先停喇叭，再取消旧 DeepSeek/TTS；
ASR 持续工作，保留新问题开头。旧轮迟到音频按 generation/epoch 作废。
只有真实排空、包含 DMA 尾部等待的短片段才进入模型历史，中途取消片段排除，并提示下一轮回答曾被打断。
这是短片段边界同步，不冒充逐字音频时间戳或人耳听到位置。

网页「音频传输统计」显示首段音频返回和首音发往喇叭的时间；
起点是这一轮回答任务开始，不含前面的 ASR 句尾等待。发送完成不等于人耳实际听到的时刻。
后台 `current_turn_timing` 的 LLM received/drained 字段包含应用背压，不能解释为模型服务端计算耗时。

## 声音通路

原始录音保持 48kHz、16bit、单声道、固定增益 12dB、ALC 关闭，不重采样、不做语音降噪或裁剪。
单独的语音分支使用 ES8311 左 ADC＋右 DAC 同步参考（0x44=0x58），双通道转为 16kHz 后
运行官方 ESP-SR FD AEC 与经典 WebRTC VAD，只有处理后的 clean PCM 发往 ASR。
TTS 返回 24kHz PCM，电脑适配为 48kHz 经板端 I2S 播放。

控制端口 80，原始录音 81，喇叭 WebSocket 82，视频 83，AEC 音频 84。
DSP-only 依赖逐文件与官方 SHA-256 校验，来源和许可在 `firmware/components/*/UPSTREAM.json`，
通过 `scripts/prepare-speech-dsp.py` 重现。原始测量与语音处理分支保持独立。

## 服务与本地凭据

| 环节 | 当前服务 | 凭据 |
|---|---|---|
| 识别 | 阿里 `fun-asr-realtime` | 阿里云 Key |
| 回答 | 现有 `deepseek-flash` | DeepSeek Key |
| 合成 | 阿里 `cosyvoice-v3-flash`，音色 `longanyang` | 同一份阿里云 Key |

`api_key/.env` 支持 `api_key:你的DeepSeekKey` 和 `aliyun_key:你的阿里云Key`，
也支持标准 `DEEPSEEK_API_KEY=`、`ALIYUN_API_KEY=`；单独 `api_key/realtime.env` 的 `DASHSCOPE_API_KEY=` 优先。
新式带点号的 sk-ws Key 已支持，不回显到浏览器、不写入固件。无需安装阿里云 CLI。

非秘密设置在 `local/realtime.json` 和 `local/ai.json`。当前全部 Direct 直连，不走 7900，
不改变系统代理或 Wi-Fi。保存配置本身不开始语音任务。
北京通用 Host `dashscope.aliyuncs.com` 已实际调用成功，也可填写账号对应业务空间的同地域专属 Host。

官方接口依据：[Fun-ASR](https://help.aliyun.com/zh/model-studio/fun-asr-realtime-websocket-api)、
[CosyVoice](https://help.aliyun.com/zh/model-studio/cosyvoice-websocket-api)、
[DeepSeek Prefix Completion](https://api-docs.deepseek.com/guides/chat_prefix_completion)、
[ESP-SR AEC](https://docs.espressif.com/projects/esp-sr/en/latest/esp32p4/acoustic_echo_cancellation/README.html)。

## 真实验证与边界

- Direct：DeepSeek HTTP 200、阿里 WS 101，见 `data/direct-network-check.json`。
- 板端 AEC：麦克风确实收到喇叭，三轮处理前后能量衰减 20.54～36.06dB，稳定段 VAD 自激为 0，
  见 `data/duplex-acoustic-check.json`。这只证明喇叭单端回声抑制。
- 真人插话：用户明确反馈“能停下原回答，并回答新问题”，见 `data/manual-duplex-user-feedback.json`。
- 文字完整性：真实 DeepSeek 一次 SSE 完整输出《滕王阁序》，首尾与十个段落标志齐全；
  强制小预算触发 length 后续写也通过，见 `data/deepseek-long-stream-check.json`。
- 长朗读：生产 DeepSeek/TTS/实板喇叭逐字核对 717/717 字，74 个片段完整排空，
  实际播放 270.548 秒音频，整轮 278.203 秒后恢复 listening。
  首非零音频提交 1.171 秒，板上 DAC 参考出现 1.578 秒。
- 长读中断：约播放 12 秒后停止确认 15ms，旧任务取消、队列清空，未播 44 字排除于历史。
  完整与中断报告见 `data/long-voice-check.json`。本次输入明确为文字测试任务，不伪装 ASR 或真人双讲。

初次长读辅助测试额外开启三路调试音频和视频，观察流发生积压并主动停止；失败证据单独保留。
最终长读使用生产 BLV1 语音流及默认 AI 页无视频负载，无缺帧，所有 TTS/喇叭/观察流已关闭。
摄像头长帧间隔与复杂背景人声区分仍是独立优化项；当前 VAD＋转写确认不等同于语义插话分类。

## 可复现检查

以下不调用收费云服务，实板检查需空闲且顺序执行：

```powershell
.\.tools\python\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
.\.tools\python\Scripts\python.exe scripts\check-speaker.py
.\.tools\python\Scripts\python.exe scripts\check-voice.py
.\.tools\python\Scripts\python.exe scripts\check-duplex-acoustics.py
```

以下实际调用已有云服务并播放实板声音，需硬件空闲：

```powershell
.\.tools\python\Scripts\python.exe scripts\check-long-voice.py
# 显式合成输入／合成VAD的全链路诊断，不冒充真人语音
.\.tools\python\Scripts\python.exe scripts\check-duplex-session.py --run-cloud
```

「连接自检（无需 API）」只检查真实收音和固定提示音回传，不执行 ASR/TTS，不证明完整 AI 会话或声学回声效果。
聚合诊断保存在 `data/voice-checks/`；生产通话不自动保存用户语音或完整转录。
