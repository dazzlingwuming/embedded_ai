# 摄像头画面进入对话上下文

本版继续使用云 ASR → DeepSeek → 云 TTS。采用现成语音流水线中的“后台持续收图，用户一轮输入结束时自动附图”模式，按 [LiveKit 官方视频示例](https://docs.livekit.io/agents/multimodality/vision/video/) 的接入时机实现于现有后台。
DeepSeek `deepseek-flash` 的图片格式按其 [官方视觉接口](https://api-docs.deepseek.com/guides/vision/)；当前没有迁移整个 Agent 框架。

## 使用

打开本机控制台的「AI 助手」，「摄像头参与对话」默认为开启。后台视频采集独立于网页预览；切到 AI 页、关闭预览或浏览器，都不会释放后台的视觉订阅。
在文字框提问，或开始原有语音通话后对麦克风提问，本轮会自动挑选至多一张近期可用图片。
「最近一次问题选图」展示同一张 JPEG 的缩略图、接收时间、候选数、画质提示及请求阶段。阶段为已选择并不表示云端已经收到，收到响应后才显示相应状态。

后台采样和本地评分不调用云模型。只有提交文字或识别出最终语音句后才调用 DeepSeek。
关闭「摄像头参与对话」后，后续对话不带图；如要修改此项，先结束当前通话或文字回答。
模型看不清时可以提出摆放、朝向、保持稳定等要求。调整后说“好了”或继续提问，下一轮用新图接着讨论。
当前还没有模型自主取图的 MCP 工具循环，也不会在没有新问题时自动持续调用视觉模型。

## 数据流与边界

```text
ESP32 的单路 MJPEG
  → CameraRelay：网页与视觉共享一个上游连接
  → VisionFrames：最多每秒评分两帧，旧 pending 被最新帧替代
  → 本地近期缓存与质量排序
  → 每次问题选至多一帧
  → DeepSeek 用户消息中的文字＋image_url 图片内容块
  → 流式文字回答／原有 TTS 与喇叭播放
```

图像评分在工作线程中完成，避免阻塞音频事件循环。只传原始 JPEG，不用插值放大图伪造细节。
接收时间是电脑收到 JPEG 的时间，尚未做板端曝光时钟同步。默认从最近 3 秒中选择，缓存保留最多 8 秒／16 张；包括正在评分和 pending 的 JPEG 总持有量限制为 12 MiB。
每张输入不超过 2 MiB、8192 像素边长、16 Mi 像素总数，并校验实际 JPEG 解码。适配器最多接受两张，当前自动附图策略只选一张。
历史模型上下文保留原有近期文字，不把每一轮原图无限累积。最近 16 组问题的选图仅在内存中保留，用于本机缩略图核对；停后台、换板子或关闭视觉时清理。

选帧先限制接收时间，并以最新帧粗外观排除明显不同的旧背景，再比较清晰度与曝光。
这种外观门控仍是启发式，不能证明候选与用户所指物体语义相关。

## 本地质量判断

在固定 96×96 灰度探测图上计算有符号 Laplacian 方差，同时记录亮度、曝光比例、低纹理标记及近重复指纹。
Laplacian 是传统图像处理算子，见 [OpenCV 官方说明](https://docs.opencv.org/4.x/d5/db5/tutorial_laplace_operator.html)。
这里采用 Pillow 解码与小图数组计算，不下载本地视觉大模型、ASR 或 TTS 模型。

这些分数用于同批候选比较，不是识别置信度，也没有通用的“超过某数就一定清晰”保证。
白墙等少纹理场景只提示清晰度难判断；接近全黑、全白或解码失败的画面不作为正常可用帧。
若入口处更新的帧尚未评分成功，等待有上限；超时或最新帧损坏时明确无图，避免拿旧图冒充当前状态。

减少发送图片数量和历史图像数量能控制图像输入用量。JPEG 压缩主要减少传输字节，模型图像 token 还与尺寸和处理规则有关，不能把文件变小直接等同于 token 按比例下降。

## 问题与解决顺序

| 问题 | 本版处理 | 后续处理 |
| --- | --- | --- |
| 晃动、模糊、曝光异常 | 近期候选排序、曝光标记、明确无图 | 用实际手持物场景标定，补目标区域质量判断 |
| 旧背景清晰但目标已经变化 | 最新外观门控、接收时间窗口、图片编号 | 与 ASR 起止时间对齐，按问题选择历史片段 |
| 小字、遮挡或标签朝向不对 | 模型可以根据本轮图像提出具体调整要求 | MCP 局部查看、补拍及等待新画面任务 |
| 静态画面误判为能理解完整动作 | 请求明确说明是单帧观察 | 按时间分段取少量关键帧，验证动作理解 |
| token 累积 | 默认一张当前图片，历史只带文字 | 明确任务需要时才增加时序帧或高细节区域 |
| 图像是否真正进入请求 | 图片编号、SHA256、阶段、同字节缩略图；传输适配器回归 | 更完整的每轮用量与延迟观测 |
| 语音和视频争用资源 | 单个视频上游、评分限频、后台线程 | 做长时间语音＋图像＋打断联测后调整板端码率 |
| 画面获取失败 | 普通聊天继续，明确本轮未附图 | 分级重连、长时间网络故障联测 |
| Agent 自主补看与向人求助 | 提示词支持提要求；用户新一句话带新图 | 完整工具循环、等待用户/视觉事件、取消与超时 |
| 认出已登记的人 | 尚未实现 | 独立注册、特征库、未知人和身份匹配 |
| 舵机转动、寻找目标 | 尚未实现 | 设备工具、角度反馈、运动后稳定判断和视觉复查 |
| 云端部署 | 当前后台仍在本机 | 现场媒体网关向服务器发送选中画面和事件 |

## 配置与验证

项目内 `local/vision.json` 保存摄像头参与设置，模板是 `config/vision.example.json`。
依赖安装仍用 `scripts/setup-console.ps1`，新加 Pillow 的版本固定于根 `requirements.txt`。

离线检查：

```powershell
.\.tools\python\Scripts\python.exe -m unittest discover -s tests -p test_*.py -v
```

`scripts/check-vision-context.py --run-cloud` 会进行注明的真实云调用；默认不运行收费验证。
自动化验证将合成图语义测试、真实摄像头生产入口、图片字节核对分开记录，不把它们当成真人语音识别或复杂真实场景的全面验收。
用户图像、采集数据、测试报告和 API Key 继续留在本机忽略目录，不提交 Git。

2026-11-13 验证：193 项软件测试通过；两张合成图的形状、颜色、随机六位数字识别正确。
用户调整真实摄像头后，模型识别出的电脑屏幕、“现场声音”标题和深色波形区与人工查看相符。
原先灰色渐变及后续模糊样本都保留在报告中，不能把传输成功当作物体识别成功。
本机汇总为 `data/vision-verification-summary.json`；真人连续语音＋视觉＋打断的长时间联测仍待进行。

## 2026-11-13 同批实拍选帧对比

保持生产选帧源码和阈值不变，新增两个实验脚本：`scripts/capture-vision-comparison.py` 和 `scripts/compare-vision-policies.py`。
三段实拍共 180 秒、3027 张原始 JPEG；使用采集前固定的 47 个时点比较“直接取最新帧”和当前算法。
覆盖实际屏幕页面切换、键盘及转向屏幕、杯状容器的稳定和晃动。脚本中的计划动作仅为提示，不作为答案。

每种策略每时点重复两次，共 188 次真实 `deepseek-flash` 请求，无重试、无 API 错误。
两边使用相同提示词、原始 800×800 JPEG、独立轮次；配对调用顺序交替。
先给图片随机编号并隐藏策略，再由本助手目视标注；标注和配对清单的 SHA256 在第一笔调用前封存。
模型只能看到本轮图片、同一问题和接收时间，不能看到策略名、分数或答案。

| --- | --- | --- |

| 屏幕状态正确次数，辅助指标 | 37/46（80.43%） | 39/46（84.78%） |

最新帧基准没有等待评分，未单独测量读内存引用的微小开销。选图等待在采集时实测，模型延迟在采集后对固定图片实测；
两者不是同一次真人语音请求的端到端计时。Token 是 API 实际返回的全请求用量，不能拆称为单独图片 Token 或人民币费用。
两边累计缓存命中输入 Token 均为 24576，计入上表输入总数，不另行相加。

明确的收益个例是杯子晃动的 `g3-d05`：最新帧两次均回答 `unclear`，当前算法两次均识别为杯子，
选中图片比提问时点早约 0.859 秒。主体识别的整体差异很小，且中心遮挡／空白表面的类别有歧义。
预先标记了三张歧义图片；同时排除涉及它们的相同配对后，辅助联合指标为 79/90 对 83/90。
保留全部样本为主结果，不根据模型输出重写标注或筛掉失误。

独立测量同批图片的 JPEG 解码和质量评分共 276 次：中位数 1.811 ms，P95 2.095 ms。
约四分之一秒的选图等待主要与半秒评分周期和等待最新待评分帧的机制有关，不能归因于评分计算本身。
34/47 次选中的是提问时点之后才接收的帧；这说明当前机制经常等待下一批评分，而非立即使用已有候选。

本轮没有证据证明当前策略在总体上稳定优于最新帧，也没有节省输入 Token；局部抗晃动收益与额外等待需要权衡。
三段连续片段的相邻时点及重复调用不是独立场景，标注未经过独立人工逐帧复核。
深色导航页与图标网格的标签边界可能重叠，屏幕状态仅作辅助指标；OCR、精细标签读取和复杂物体尚未测量。
