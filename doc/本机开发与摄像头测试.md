`firmware/` 已整合摄像头、麦克风、喇叭和网络仪器网关，正在实际开发板运行。
用户调整镜头后可见墙面和天花板边线；完整画质仍需用有纹理的物体检验，不能把有画面等同于对焦验收。

- 板子 COM5，主芯片 P4 rev3.1，16MB Flash、32MB PSRAM，OV5647 摄像头和 ES8311 声音模块。
- 电脑与板子实际接入 `现场Wi-Fi（名称已脱敏）`，板子为 2.4GHz 信道 6、IP `192.168.2.38`；电脑为同局域网的 5GHz 接入点。
- 本机控制台 <http://127.0.0.1:8765/> 同时提供视频、音频和 AI 页面。Type-C 用于供电、烧录及串口，音视频走 Wi-Fi。
- ESP-IDF 5.5.4、ESP-Hosted 1.4.6、esp_wifi_remote 0.14.5、esp_video 2.6.0，精确组件见 `firmware/dependencies.lock`。
- 摄像头和 ES8311 共用 GPIO7/8 的 I2C 总线；未改写 C6 出厂固件或 eFuse。
- 控制端口 80、原始收音 81、喇叭 WebSocket 82、MJPEG 视频 83、AEC 语音流 84。800×800 JPEG 预览编码上限 20fps。
- 独立语音分支使用官方 ESP-SR AEC 与 WebRTC VAD，默认自动插话；原始测量 WAV 不应用这些处理。


全部工具、缓存和日志在本项目目录；临时 P: 仅作中文路径别名。Wi-Fi 私有配置在 `local/wifi.json`。

## 当前验证与未完成项

现场用户已确认喇叭能发声，但原默认音量 20 太小；自检另外限制到 10，导致提示音难以听到。
0.5.1 将音量范围恢复为驱动标准的 0～100，默认 75，并增大、延长自检提示音；录音增益不变。

0.6.0 已完成 128 项软件检查和 15 项实板联合检查。四节点稳定查询 30.84 秒、17 轮，
包括故障注入在内录音 62.24 秒、1058 张 JPEG，WAV 无缺帧、无中断、无重启。
长朗读样本 717 字逐段获实板排空确认，音频时长 270.548 秒，验证超过原 30 秒和 90 秒截断点。
证据见 `logs/final-unit-tests.log`、`data/hardware-verification.json`、
`data/long-voice-check.json` 和 `data/duplex-verification-summary.json`。
历史 0.5.0 的 181.48 秒联测另存为 `data/hardware-verification-v0.5.0.json`。

视频曾测得平均约 17.2fps，但历史窗口最长帧间隔达到 1391ms、最慢 1% 约 2.7fps。
网页已经展示这些指标并采用最新帧缓存；仍有长间隔，未完成卡顿根因和持续低延迟验收。
原始录音为 48kHz、16bit 单声道，固定增益 12dB、ALC 关闭，不做降噪、VAD、AGC 或静音裁剪。

语音按云 ASR → DeepSeek → 云 TTS 实施；文字回复边生成、边合成、边播出，正常长读不再按总时长截断。
用户已经确认可以说话打断旧回答并得到新回答；实板喇叭单端 AEC 测试也通过。
复杂噪声、双讲识别质量和长期稳定性仍需另行评估，具体见 `实时语音接入与自检.md`。
尚未接入实体 USB 仪器、Hub、电机，也没有实现通用 USB-over-IP。

## 文件位置

- `camera/`：从微雪 `17_simple_video_server` 派生的摄像头工程。
- `sources/`：官方 ESP32-P4-Platform 示例源代码。
- `.tools/`：项目专用 Python、ESP-IDF v5.5.4、编译器等工具。
- `.cache/`：下载、临时文件、组件和 pip 缓存。
- `.build/`：基础检查和摄像头固件的独立构建结果。
- `backups/`：原厂完整 Flash 备份和 SHA-256 记录。
- `local/wifi.json`：私有 Wi-Fi 配置，不要分享或提交公开仓库。
- `local/wifi_credentials.h`：生成的私有配置头文件，固件包含其中凭据。
- `logs/`：安装、构建、烧录与串口日志。
- `data/`：真实摄像头截图、接口返回值和短时视频流验证结果。

所有新工具和缓存保存在本项目目录中。不做全局安装或永久修改 PATH。
为兼容嵌入式工具对中文路径的限制，开发脚本临时使用 `P:` 指向项目目录，
并在项目专用 Python 子进程内保留这个路径别名，避免被还原成中文路径。
它只是路径别名，没有将文件搬到其他目录。代理设置仅作用于当前进程。

本次官方源代码提交：ESP32-P4-Platform `6f78fa810ec505048c1941e3d09cefc9f29129bd`；
ESP-IDF v5.5.4 `735507283d5b2f9fb363a1901172dbd9e847945d`。
摄像头依赖的精确版本记录在 `camera/dependencies.lock`。

## 修改 Wi-Fi

编辑 `local/wifi.json` 中的网络名称和密码，再重新编译、烧录。
SSID 使用 UTF-8，长度最多 32 字节；WPA2 密码 8～63 字节。
程序启动后先尝试列表中的第一个网络，连接失败后轮换尝试后续网络。
当前优先使用 ATL 网络；现场扫描确认 `现场Wi-Fi（名称已脱敏）` 同名下存在
2.4GHz 信道 11 的接入点，电脑当前连接的是其 5GHz 接入点。
新增配置后无需修改 C 源码。当前不提供板上网页配网。

摄像头预览要求电脑和开发板在同一局域网，不要求该局域网能访问互联网。
下载开发工具与依赖需要互联网；手机热点应支持 2.4GHz。

## 编译与烧录

在项目根目录打开 PowerShell：

```powershell
.\scripts\build-flash.ps1 -BuildOnly
.\scripts\build-flash.ps1 -Port COM5
```

烧录将替换 P4 上运行的程序。摄像头固件和以后麦克风测试固件不能靠
分别烧录来叠加功能；联合采集时需要整合进同一应用。

查看串口并复位：

```powershell
.\.tools\python\Scripts\python.exe .\scripts\serial-log.py --reset --seconds 30
```

启动日志输出 `Camera address: http://.../` 后，在同一网络的浏览器打开该地址。
本次实测地址为 `http://192.168.2.38/`，路由器重新分配地址后可能变化。
原始官方预览页面由板端提供，端口 80 提供页面，端口 81 提供 MJPEG 流。

## 恢复原固件

原固件已在首次烧录前完整读取，文件为
`backups/factory-esp32p4-16mb.bin`（16,777,216 字节），校验值在同目录 JSON 中。
需要恢复时，在板子连接 COM5 的情况下执行：

```powershell
.\.tools\python\Scripts\python.exe -m esptool --port COM5 --baud 921600 write-flash 0 .\backups\factory-esp32p4-16mb.bin
```

此命令只写回 Flash，不涉及修改 eFuse。

## 已知限制

- ESP-Hosted 主机组件为 3.1.0，板载 C6 上现有固件通过旧版兼容握手工作；
  日志将其版本报告为 0.0.0，并提示版本不一致。目前已通过 Wi-Fi 和短时
  视频流测试，未升级或覆盖 C6 固件。正式联合负载前需复核版本组合与稳定性。
- 当前固件只验证视频；板载麦克风和喇叭未初始化，喇叭保持静音。
- 路由器接入点扫描是当前时刻的结果，不能仅凭 SSID 名称判断频段。
- 当前保存网络轮换连接；还没有网页配网和动态修改凭据功能。

## 后续实施顺序

本节依据原始交接文档整理实施建议，不表示这些功能已经实现。

| 顺序 | 实施内容 | 验收依据 |
|---|---|---|
| 1 | 板载麦克风单项采集，经 Wi-Fi 在电脑监听并保存 WAV | 真实录音可回放，采样率/位宽/声道/固定增益明确，报告中断与丢包 |
| 2 | 在同一固件整合视频和音频，电脑保存同次测试记录 | 同时看到真实视频、听到真实声音，持续运行并观察资源与断线行为 |
| 3 | 增加模拟仪器的双向命令通道与电脑最小界面 | 请求编号、目标设备、响应与结果可追溯，模拟曲线显著标注来源 |
| 4 | 实测单台 USB 设备，再接独立供电 Hub 和多个设备 | 实物 VID/PID、设备类、拓扑和速率；逐一确认实际驱动和协议 |
| 5 | 接入一台真实仪器，再接电机控制器 | 型号与手册确认后先只读，写参数需独立确认真实设备边界 |

麦克风第一版建议从 48kHz、16bit、单声道 PCM/WAV 开始，作为待验证的配置，
不默认开启语音降噪、AGC、VAD 或静音裁剪。固定增益可配置，喇叭不回放采集声音。
48kHz/16bit/单声道的原始音频约 96KB/s；实际可用频响仍由麦克风和采集电路决定。

已检查官方 `12_I2SCodec` 示例：提供 ES8311/esp_codec_dev 路径，默认偏向音乐播放，
不能直接视为符合噪声采集要求的成品。其 I2C SDA=7、SCL=8 与摄像头共享，
联合固件需共用 I2C 总线和一致的驱动，不重复创建冲突的总线实例。

当前 ESP-IDF v5.5.4 源码包含外部 Hub 支持选项；这一点不等于已验证三四台 USB
仪器，也不等于通用 USB-over-IP。后续必须按实际设备类实现驱动和仪器协议。
