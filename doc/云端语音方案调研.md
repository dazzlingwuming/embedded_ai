# 云端语音方案调研与当前决定

核对日期：2026-11-12。用户目标：ESP32-P4 麦克风输入、开发板喇叭输出，
体验接近连续语音通话。用户明确不采用本机运行语音识别、语音合成模型。
此前本地模型下载方案已停止，相关安装脚本已移除，没有实际安装语音模型。

## 成熟方案怎样实现

**串接式：云 ASR → 文字大模型 → 云 TTS。** ASR 将语音识别为文字，LLM 处理内容，
TTS 将回复合成为声音。这是给现有 DeepSeek 添加语音入口和出口的直接路径。
要减少等待，通常将识别、模型输出、合成和播放做成流式，并管理会话、断句、打断和取消。
语音识别属于转写，不需要先把中文翻译成另一种语言。

**端到端：语音模型直接处理声音并生成声音。** 音色、节奏、轮流说话与打断由实时语音
服务协同处理。它需要该语音服务的接入资格，不能把 DeepSeek 的文字 Key 直接当成另一家
语音服务的 Key。设备端依然需要稳定的收音、播放、网络传输和回声处理。

[OpenAI 官方 Voice agents](https://developers.openai.com/api/docs/guides/voice-agents)
明确区分可更换各环节的串接式管线、Realtime 语音模型，以及可与独立后端配合的全双工语音层。

## 用户提到的产品

| 产品或项目 | 公开资料能够确认的情况 | 对本项目的意义 |
|---|---|---|
| DeepSeek | 当前官方 Chat Completions 提供文字、图像等输入；没有公开可直接用于本项目的 ASR/TTS 接口 | 已有 Key 可承担 LLM，云语音识别和合成另行接入 |
| ChatGPT / OpenAI | 开放的 Realtime API 支持直接语音到语音；官方也提供串接式架构说明 | 可借鉴会话、流式音频、打断与取消机制；OpenAI API 需自己的凭据 |
| 豆包 / 火山引擎 | 公开语音识别、流式语音合成和端到端实时语音服务；公开接口有流式双向传输方案 | 中文云语音的可选供应方；保留 DeepSeek 时选独立 ASR/TTS 路线 |
| Anthropic / Claude | 官方确认 Claude 产品提供连续语音对话、自然停顿响应和说话打断 | 产品功能不能证明其内部 ASR/TTS 供应链或普通模型 API 直接兼容音频 |
| 小智 ESP32 | 开源固件定义语音上传、识别文本、TTS 开始/音频/停止以及中断等协议 | 最贴近本项目硬件场景的现成参考 |

上述说明对应公开产品能力和接口，不声称掌握豆包、Claude、DeepSeek App 的未公开内部实现。
App 有麦克风按钮，与它的开发者文字 API 是否开放音频输入，是不同的能力边界。

## 已具体核查的开源嵌入式做法

[78/xiaozhi-esp32](https://github.com/78/xiaozhi-esp32) 的
[WebSocket 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket_zh.md)
使用 JSON 控制消息和二进制 Opus 音频：设备上传声音，服务器返回 stt 文字和 TTS 音频，
并处理开始监听、开始/停止播报、会话和中断。它还提供实时语音模型接入方向；
具备 AEC 条件的硬件可进一步支持全双工。

[xinnan-tech/xiaozhi-esp32-server](https://github.com/xinnan-tech/xiaozhi-esp32-server)
是独立的开源服务端项目，支持流式 ASR/TTS，LLM 列表包括 DeepSeek；
语音供应方包括火山、阿里百炼、讯飞、腾讯等，也允许本地实现。
因此可参考它的云供应方适配和会话控制，选择云服务不要求在本机部署语音模型。
开源的是框架、协议或模型代码；商业 App 的整套语音服务不一定开源。
云服务的账号、额度、计费和服务规则仍需按供应方当前说明配置。

## 对当前项目的路线

用户已明确选择并完成接入 **云 ASR → DeepSeek → 云 TTS**。原先预接的直接语音问答路线已撤出实际通话路径，价格比较仅保留作历史参考。

```text
板子麦克风 → 电脑中转 → Fun-ASR-Realtime → DeepSeek
板子喇叭   ← 电脑中转 ← CosyVoice        ← 文字回复
```

当前使用 `fun-asr-realtime`、已有的 `deepseek-flash` 和 `cosyvoice-v3-flash`，音色 `longanyang`。
ASR 和 TTS 使用用户同一份百炼 Key，DeepSeek 沿用单独的 Key，均从项目本地配置读取，不下发到板子或浏览器。
实际调用已验证北京通用 Host 可用，无需安装阿里云 CLI，也无需安装本地语音模型。

中转服务先运行在本机，识别、回答和合成计算在云端。音频格式转换、分帧和缓存是传输处理，
不会把原始测量 WAV 改为语音专用采样率。DeepSeek 只接收 ASR 识别文字，不接收摄像头视频或原始声音。

当前 0.6.0 使用独立 AEC/VAD 语音分支，默认持续监听并支持自动插话，用户已确认能停下原回答并回答新问题。
实板喇叭单端回声抑制通过，三轮衰减 20.54～36.06dB；复杂双讲和长期稳定性没有据此视作完成。
此前真实云端两轮 ASR → DeepSeek → TTS 检查使用合成语音样本，未冒充真人识别准确率评测。
生产通话与原始录音互斥；原始测量 WAV 保持原格式、固定增益，不应用 AEC/VAD。

已实现边生成边合成播放，移除正常长回复的 30 秒音频和整轮 90 秒截断。
真实 DeepSeek/TTS 加实板喇叭完整播放《滕王阁序》717 字长读样本，270.548 秒音频全部排空。
该长读输入为文字测试任务，不把它等同于麦克风 ASR 验收。Direct 直连已验证，不走 7900。
0.6.0 音视频加四台软件仪器的 15 项联合检查通过，原始 WAV 无缺帧、无中断；
视频仍有长帧间隔，不能宣称卡顿已经解决。聚合证据在 `data/duplex-verification-summary.json`。
具体操作、调用脚本和验证边界见 [实时语音接入与自检](实时语音接入与自检.md)。

## 实时语音 API 价格核对（2026-11-12）

以下为官方公开标准价，音频输入/输出单价按每百万音频 Token；国内模型列北京/通用人民币价，
海外模型保留美元原价。每分钟估算假设用户说 30 秒、模型说 30 秒，只计新增音频；
美元按 7 元/美元作预算换算，不是实时汇率，不包含文本、历史上下文、工具、税费和地区差价。

| 模型 | 音频输入 / 百万 Token | 音频输出 / 百万 Token | 每分钟新增音频估算 |
|---|---|---|---|
| 阿里 qwen3.8-omni-flash-realtime（北京） | 6 元 | 12 元 | 0.00576 元 |
| 阿里 qwen3.5-omni-flash-realtime（北京） | 27 元 | 107 元 | 0.045795 元 |
| Google Gemini 3.8 Live | 3 美元 | 12 美元 | 按官网每音频分钟折算约 0.0115 美元，预算约 0.08 元 |
| OpenAI gpt-realtime-2.1-mini | 10 美元 | 20 美元 | 0.015 美元，预算约 0.105 元 |
| 豆包实时语音（官方通用价格项） | 80 元 | 300 元 | 0.24 元 |
| OpenAI gpt-realtime-2.1 | 32 美元 | 64 美元 | 0.048 美元，预算约 0.336 元 |

计算依据：阿里上述模型输入每秒 7 Token、输出每秒 12.5 Token；OpenAI Realtime 输入每秒
10 Token、输出每秒 20 Token；豆包输入每秒约 6.25 Token、输出每秒约 25 Token。
Gemini 价格页直接给出音频输入约 0.005 美元/音频分钟、输出约 0.018 美元/音频分钟，
本表使用其官方近似数计算。不同厂家的 Token 定义不同，不能直接以单个 Token 报价比较成本。

这些数值是新增音频的预算参考。多轮历史内容会重复作为输入处理，文本也可能另外计费，
所以不能把 0.00576 元等估算直接当成长时间连续通话的全包单价。
阿里 qwen3.8 的音频和对应文本分别计价；OpenAI 和 Gemini 也有文本及上下文计费。
豆包价格页没有单独列明 Seeduplex 3.0 SKU，本表不把通用价格项冒充其专属报价，需在开通时核对。

此外，OpenAI gpt-live-1 的语音会话层为 0.05 美元/分钟，按秒计费，预算约 0.35 元/分钟；
后端模型和工具另计。该路线可以采用独立后端，但需要 OpenAI 服务的凭据和接入条件。

从公开新增音频报价看，可优先小规模验证 Qwen3.8-Omni-Flash-Realtime 的中文效果与真实 usage；
是否替换当前 DeepSeek 问答路线，需要同时考虑对话模型、听感、延迟和可用地域。
使用原生实时语音模型时，通常由该模型负责语音交互和回复；保留 DeepSeek 作为问答大脑时，
独立 ASR/TTS 或带独立后端的语音层需要分别核算。
